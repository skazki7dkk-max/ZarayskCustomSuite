# Обновление 0.1.1 — приоритет и диагностика

Для сервера с CS2MenuManager-MenuManager v44 (Miksen). Совместимый публичный метод `CS2MenuManager.API.Class.MenuManager.CloseActiveMenu(CCSPlayerController)` находится в уже загруженной библиотеке: чужая DLL не заменяется. Источник контракта: https://github.com/schwarper/CS2MenuManager/blob/main/CS2MenuManager/API/Class/MenuManager.cs . Фактическая совместимость установленного форка показывается командой диагностики, на сервере пользователя ещё не проверена.

## Установка

1. Замените `ZarayskMenu.dll` и `ZarayskMenu.deps.json` из `server/game/csgo/addons/counterstrikesharp/plugins/ZarayskMenu/`. Старый `menu.json` можно оставить: новые параметры по умолчанию включены. Shared API не менялся.
2. Перезапустите сервер. Проверьте, что `css_plugins list` показывает **0.1.1**.
3. Для повышения слоя отрисовки обновите CSS-ресурс из `workshop/zaraysk_menu/panorama/styles/custom_game/` в своём аддоне **3809867620** и опубликуйте обновление. Серверный приоритет работает и со старым ресурсом; новый z-index требует обновления аддона и перезапуска клиента. z-index работает в пределах соответствующего UI-дерева и не гарантирует превосходство над любым чужим HUD.
4. В конфиге MultiAddonManager проверьте, что `mm_client_extra_addons` содержит `3809867620` (сохраните остальные ID). Сам Workshop ID не доказывает, что аддон скачался и содержит правильные файлы.
5. В консоли ИГРЫ, не RCON, введите ровно **`css_zmenu_open`**. В чате — `!zmenu_open`. Между css, zmenu и open стоят подчёркивания, не пробелы. Команда не переключает уже открытое меню обратно в закрытое.

Команда подтвердит обработку запроса. Если окна нет, выполните **`css_zmenu_status`** в консоли игры и пришлите весь вывод вместе с ошибками клиентской консоли. `active/entity/session/capture` подтверждают лишь серверное состояние, не загрузку XML клиентом. Если команда неизвестна — загрузилась не новая DLL либо плагин не загрузился. Ищите ошибку в журнале CSS.

## Что изменено

- Пока наша сессия открыта, каждые 250 мс закрываются активные меню стандартного CSS MenuManager и совместимого CS2MenuManager только для этого игрока. WeaponPaints/Warcraft могут продолжать работать, однако их меню через эти менеджеры будут закрываться до выхода из нашего.
- При `CaptureMouse=true` у остальных `custom_hud_layout` отключается захват ввода этого игрока, затем курсор отдаётся нашему HUD. Сами чужие сущности не удаляются, их видимость не меняется. После выхода чужое меню нужно открыть заново: старый захват ввода не восстанавливается вслепую.
- Добавлены `PriorityEnabled=true`, `SuppressOtherHudInput=true`. При конфликте с важным чужим интерфейсом можно отключить второе; первое отключает весь механизм приоритета.
- Состояние отрисовки повторно отправляется через 0.15, 0.5 и 1.5 секунды после открытия. Повторы не возрождают закрытую сессию и не продлевают тайм-аут.
- Добавлены явная команда открытия, сообщения ошибок и диагностика API другого менеджера.

В 0.1.0 не было интеграции с CS2MenuManager. Это найденный недостаток, но без диагностики клиента нельзя утверждать, что именно он был причиной невидимого окна. Отсутствующий/неверно упакованный Panorama-аддон этот патч не заменяет.

## Проверка

Сборка .NET и Resource Compiler выполнены локально. Автотесты проверяют также обнаружение совместимого внешнего API, вызов и обработку его исключения на тестовом двойнике. Живой Linux-сервер с форком Miksen и Workshop-аддоном пользователя здесь не запускался.
