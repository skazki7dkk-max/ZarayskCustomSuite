# Мост для C++ / Metamod 1472

Это серверный командный протокол, а не отдельный native-рендерер. На сервере также нужны CounterStrikeSharp 1.0.375 и ZarayskMenu.

Добавьте в `menu.json` меню и пункт (например, в `main.Items`):

```json
{"Id":"native_vip","Text":"VIP: действие C++","Permission":"@css/reservation","ServerCommand":"myvip_menu_action {slot} {userid} {steamid}"}
```

Зарегистрируйте в своём Metamod-плагине серверную команду `myvip_menu_action`. При вызове:

1. Отвергайте вызовы от клиентов: принимать только серверный контекст команды.
2. Ожидайте ровно три числовых аргумента: slot (0-based), userid, SteamID64.
3. Найдите текущего игрока и сравните ВСЕ три значения. Иначе повторно занятый slot может указать на другого игрока.
4. Повторно проверьте права/состояние в вашем плагине. Флаг меню не заменяет авторизацию игрового действия.
5. Выполните действие.

Чтобы C++-плагин открыл меню, отправьте через серверный command buffer (обычно `IVEngineServer2::ServerCommand`) строку:

```text
zm_open 3 76561198000000000 main
```

В конце строки для command buffer добавьте `\n`. Используйте настоящий slot/SteamID игрока. Идентификатор меню — только `[A-Za-z][A-Za-z0-9_]{0,47}`. Не подставляйте имена игроков или произвольный клиентский текст в строку команды.

`zm_open` принимает команды только из серверного контекста и сверяет SteamID. `zm_reload` перечитывает меню. Оба доступны из консоли сервера/RCON, не из консоли игрока.

JSON можно генерировать вашим плагином с атомарной заменой файла и затем вызывать `zm_reload`. При ошибке конфигурации остаётся предыдущая версия. Для динамических C#-меню используйте типизированный API.

Сам C++ обработчик зависит от архитектуры будущего VIP/админ-плагина и здесь не реализован; вызов мостом не означает, что соответствующий игровой плагин уже установлен.
