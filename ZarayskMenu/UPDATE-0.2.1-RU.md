# Исправление Linux и интеграция WeaponPaints — 0.2.1

## Установка поверх 0.2.0

1. **Полностью остановите процесс сервера.** Одного `css_plugins reload` недостаточно: .NET запоминает ошибку статической инициализации SQLite, а загрузчик использует копии библиотек в `/tmp`.
2. Сохраните резервную копию текущих папок плагинов и `ZarayskMenu/menu.json`.
3. Скопируйте `server/game/csgo/` из этого архива в `game/csgo/` сервера с заменой файлов. Обязательно обновите `ZarayskMenu.dll`, общую `shared/ZarayskMenu.Api/ZarayskMenu.Api.dll`, `WeaponPaints.dll` и `WeaponPaints.deps.json`, а также `WarcraftPlugin/runtimes/linux-x64/native/libe_sqlite3.so`.
4. Обновлённый `ZarayskMenu/menu.json` добавляет раздел «Скины и аксессуары». Если вы изменяли меню вручную, перенесите из образца пункт `skins` и одноимённое подменю в свой конфиг.
5. Не удаляйте и не заменяйте базы Warcraft и настройки `configs/plugins/WeaponPaints/`: пакет их не содержит. MySQL-параметры WeaponPaints остаются вашими. Существующий `gamedata/weaponpaints.json` оставьте на месте: в этом обновлении он не меняется.
6. Запустите сервер заново. Проверьте журнал загрузки Warcraft/WeaponPaints, затем `!menu`, `!skins`, `!knife`, `!gloves` и `!helpwar`.

Пакет предназначен для вашего существующего сервера CounterStrikeSharp 1.0.375/.NET 10 на **Linux x86_64 с GLIBC**. Это не сборка для Alpine/musl. Клиентский Workshop ZarayskMenu остаётся прежним.

## Исправление SQLite

Ошибка из присланного лога возникла в `libe_sqlite3.so`, перенесённой из исходного Warcraft. Её ELF-зависимости требуют GLIBC 2.33 и 2.34. Для этого обновления **SQLite 3.53.3 пересобрана из официального исходника**, без отката на старую версию и без замены системной GLIBC.

Цель компиляции: `x86_64-linux-gnu.2.17`. В готовом ELF найдены только символы GLIBC 2.2.5 и 2.14. Все 359 экспортов `sqlite3*` исходной библиотеки сохранены, включая стандартные заглушки key/rekey, возвращающие SQLITE_ERROR. Библиотека не добавляет шифрование. Проверен SHA3 исходника и совпадение SQLite source ID.

SHA256 новой библиотеки: `792aa725502fc140a14f476b07930c21b48bb00e28e8d2aa49f0f83c1076999d`.
Меняется только нативная библиотека Linux x64; файлы баз и managed-провайдер SQLite не меняются. Сборка воспроизводится через `tools/build-sqlite-linux.ps1`. Сведения об источниках — в `THIRD-PARTY-0.2.1.md`.

## WeaponPaints внутри ZarayskMenu

Меню ножей, перчаток, скинов, агентов, музыки, значков, наклеек и питомцев перенаправлены в общий интерфейс. Callback получает исходное название предмета: оформление меню не меняет значение, по которому WeaponPaints выбирает скин. Сохраняются исходные игровые проверки, сохранение в MySQL и логика применения предметов.

В вашей DLL ссылки на шесть типов CS2MenuManager перенаправлены на специальный адаптер в **ZarayskMenu.Api**. Все шесть используемых сигнатур методов проверены. Отдельная поддельная `CS2MenuManager.dll` не устанавливается; остальные плагины со своей зависимостью CS2MenuManager не изменяются.

Удалена регистрация команды выбора стиля меню WeaponPaints: она занимала `!menu`, которое теперь принадлежит ядру. Для WeaponPaints используется единый стиль ZarayskMenu. Остальные 1011 тел методов совпадают с исходником с учётом переноса имён типов адаптера. Старая зависимость CS2MenuManager удалена также из `WeaponPaints.deps.json`.

SHA256 поддерживаемой исходной WeaponPaints.dll: `D3335137DA7C5DF8C1D851AF84F42A3B8A08D3FD2C8A5AD7624C16B150878DC7`.
Патчер `tools/WeaponPaintsPatch` предназначен только для этой DLL. Для будущего обновления WeaponPaints требуется повторная адаптация.

Пункты общего меню используют стандартные команды вашего плагина: `css_skins`, `css_knife`, `css_gloves`, `css_agents`, `css_music`, `css_pins`, `css_stickers`, `css_pet`. Если в конфиге WeaponPaints они переименованы, измените `PlayerCommand` соответствующих пунктов `menu.json`. Команды исполняются в контексте игрока, а не через RCON.

## Что проверено

- Release-сборка без ошибок и предупреждений.
- 47 автоматических проверок, включая передачу меню в ядро, сохранение исходного текста предметов, большие каталоги, проверку команд и отсутствие зависимости CS2MenuManager у изменённой DLL.
- CLR разрешает типы адаптера и компилирует фабрику меню WeaponPaints (JIT preparation). Полный `Load` плагина требует CS2; вне игры он не запускался.
- Статическая проверка ELF, версий GLIBC, source ID и экспортов новой SQLite.
- Живой Linux/CS2 в этой среде отсутствует, поэтому запуск на вашем сервере, отображение окон и применение предметов ещё требуют игровой проверки. Устранены конкретные зависимости из присланного лога; отсутствие любых других ошибок сервера не гарантируется.
